## A guide to setting up k3s server with my repsitory

### Setting up server with users and nodes

Firstly we need to clone this repository 
```bash 
git clone https://github.com/Kebertr/homeserver-gitops.git
```

```bash
cd homeserver-gitops
```

For a single node cluster
```bash
curl -sfL https://get.k3s.io | sh -
```

For embedded etcd(at least 3 nodes)
```bash
curl -sfL https://get.k3s.io | sh -s - server --cluster-init
```

Check if k3s started successfully on system
```bash
sudo systemctl status k3s
sudo systemctl is-enabled k3s
sudo systemctl is-active k3s
```
If k3s is not active(running) then run 
```bash
sudo systemctl enable --now k3s
```

If we want to run everything with just kubectl instead of k3s kubectl we run 
```bash
mkdir -p "$HOME/.kube"
sudo cp /etc/rancher/k3s/k3s.yaml "$HOME/.kube/config"
sudo chown "$(id -u):$(id -g)" "$HOME/.kube/config"
chmod 600 "$HOME/.kube/config"
```

To see all running nodes
```bash
kubectl get nodes -o wide
```

Get the node token from k3s
```bash
sudo cat /var/lib/rancher/k3s/server/node-token
```

To join with another machine as server on the etcd. On the new machine run
```bash
curl -sfL https://get.k3s.io | \
  K3S_TOKEN="<k3s-token>" sh -s - server \
  --server "https://<ip-addr>:6443"
```

As a worker
```bash
curl -sfL https://get.k3s.io | \
  K3S_TOKEN="<k3s-token>" sh -s - agent \
  --server "https://<ip-addr>:6443"
```

To check status on new server use same command as above. For agent run 
```bash
sudo systemctl status k3s-agent
```
You want to see active(running) otherwise start is with 
```bash
sudo systemctl enable --now k3s-agent
```

### Setting up all the applications
From root in homeserver-gitops directory, which you should be in

Install Argo CD:

Create namespace, otherwise I think it will complain
```bash
kubectl create namespace argocd
```

then
```bash
kubectl apply -n argocd --server-side --force-conflicts \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
```

Apply root or app of apps
```bash
kubectl apply -f root-application/root.yaml
```

For everything to be up and running we need to add kubernetes secrets aswell. Since several services have value files that reads the secrets
| Secret | Namespace | Purpose |
|---|---|---|
| `image-updater-git-creds` | `argocd` | Image Updater Git write-back |
| `tunnel-credentials` | `Cloudflare` | Cloudflare |
| `kong-db-credentials` | `Kong` | Kong PostgreSQL |
| `grafana-admin` | `monitoring` | Grafana administrator |
| Keycloak database secret | `keycloak` | Keycloak PostgreSQL |
| Keycloak admin secret | `keycloak`  | Initial Keycloak administrator |
| `minio-secret` | `minio` | MinIO credentials |
| `bong-postgres-credentials` | `valhall` and `valhall-dev` | Bong database |
| `member-postgres-credentials` | `valhall` and `valhall-dev` | Member database |
